# 发现路径：从具体交易向外走（历史入口表）

> **v2优先级说明**：本文件提供最初搜索与异常线索，不定义全部研究深度。新版[现场逆向SOP](field-method.md)要求入选候选继续追买方、同类竞品、上游、流量与交付；下文“沿异常追一跳”只适用于初筛，**不能作为深拆最多追一跳的上限**。总体目标和验收以[宪章](charter.md)、[v2验收](acceptance-v2.md)和[任务002](../tasks/002-opportunity-intelligence.md)为准。


用于获授权的只读平台浏览；恢复授权与当前运行见任务源。下面是采样入口，不是推荐生意，也没有预设赢家。

## 先选可被推翻的交易问题

用户已授权参考其商业认知资料和Sisuself-skill。先按当前任务读取相关模式、来源年代与个人约束，每个小批可先带最多三个具体问题，避免同时追不清；这不是整个调研的领域上限，也不限制沿分类或需求大厅独立发现。每个写明谁买什么、现成供给在哪里、为什么需要新人、什么证据会排除该方向。材料是选题线索，不是现行市场证据；私有正文不复制到本库。

优先排除必须先大量囤货、先形成成熟私域、依赖不明授权或无法验收交付的方案。对低价入口，先核完整规格、物流和售后；对服务撮合，先核买方为什么不直接找上游；对AI提效，先核客户愿意为哪个结果支付。不要因用户会AI而预设必须卖AI，也不因旧故事有利润就跳过验证。

选题后先访问一条具体交易或需求详情，再选一个能区分机制的对照或负样本。新发现若比原模式更有信息量，可以换方向并写原因；若只看到免费替代、旧需求或无法确认规格，结束该方向的小批，不继续堆相似页面。

## 从案例库补覆盖

认知案例的核查与遗漏选题见[案例覆盖补充](../reports/case-coverage-2026-10-19.md)。先查案例库和汇编，再沿可能改变判断的出处追读；目录数量、卡片数量与独立交易数量分开。同一故事的整理稿、框架和卡片不增加来源独立性。

用“谁在什么时点需要什么结果、现有渠道卡在哪、谁负责交付”改写案例。按买方、触发、交付与渠道机制和已有路线比对：看过零件不等于核过耗材补货，看过菜单不等于核过商家产品资料维护。新增假设单列，不写入现场样本批次；原文只是方案或挂牌算术时保留这个层级，不把新想法反写成历史事实。

从问题与公开正常入口找人，而非只搜项目名：临时缺货、数量不够起订、借几天、归还缺件、改版后资料没同步、到期补充、活动前缺材料。词语仅是拟议入口，未搜索的写未搜索；还要沿分类、店铺SKU与公开售后问题交叉检查。每批少量问题不是全局方向上限，具体现场发现可替换案例引导的路线。

## 六种入口

| 采样方向 | 进入后实际看什么 | 关键反证 |
| --- | --- | --- |
| 闲鱼/淘宝服务 SKU 与定制 | 具体服务页 → 同店不同档位 → 公开评价/问答 → 同类店；记录低价档、加急、返工、是否自带材料 | 低价只是咨询/定金；指标来自全店；高价包含额外工作；只有发布没有成交信号 |
| 转包、白牌、交付撮合 | 公开明确需求 → 可履约供给页；匹配规格、时限、修改、权利和验收条件 | 买家可直接找到同一供给；中间人的工时与售后吞掉价差；供应商禁止转包 |
| 1688 与零售价格差 | 前端 SKU → 尺寸/材质/规格 → 上游同规格报价、起订量、代发和附加费 | 同图不同货；阶梯价需大量采购；零售包括包装、授权或安装；退货/运费未知 |
| 小红书公开需求与成交路径 | 具体笔记 → 公开求购/询价/抱怨 → 公开商家服务页；仅记公开引导到何种入口 | 评论过期、广告或泛互动；看不到付费与履约；只留联系方式不代表订单 |
| 利基数字产品、模板、代找 | 特定用途与用户场景 → 版本、预览、更新和许可 → 公开售后问题 | 可免费取得同等内容；授权不清；标题承诺与实际交付不符；更新维护成本高 |
| 其他冷门交易/海外本地化 | 先找到实际交易页面，再追客户痛点、现有替代和本地供给 | 只看到成功叙事；国内规则、语言、支付、渠道或售后条件不同；无法合法交付 |

## 关键词搜不到时，先判断发生了什么

空结果可能来自用词不同、平台收录不足、账号/地区差异、商品下架、登录限制、真实需求少或规则限制。不要直接写“市场空白”或“关键词被封”。只有平台明确提示才记录提示事实；原因仍可能未知。

按成本从低到高换合法入口，并记录每条路线和结果：

1. **换用户说法**：用途、使用场合、想解决的问题、成品叫法、行业公开别称；保持目标含义，不用暗语掩盖违规交易。
2. **换规格入口**：材质、尺寸、交付格式、适用设备、工期、数量等可观察属性。
3. **从分类进入**：平台公开分类、服务栏目、正常筛选和排序。
4. **从店内进入**：已观察商家的 SKU、服务组合、公开展示案例和相关商品。
5. **从公开问题进入**：评价、问答、笔记评论里的缺货、改版、加急或特殊规格，再找对应公开供给。
6. **做跨平台对照**：将同一用途与规格在另一平台正常搜索，确认是平台可见性差异还是供给差异。

每条路径有时间预算。仍无结果就留下负样本和证据缺口，切换其他样本；不反复刷新、不扩大自动化采集，也不绕过验证码、反爬、登录、地区或其他访问控制。封闭 App 没进去就写未进去；开放网页、搜索摘要和第三方文章不能标成 App 实测。

## 沿异常追一跳，而不是无限扩散

看到值得留意的细节后，最多先追一个能改变判断的关联页面：一个同类竞争者、一个上游供给、一个公开需求或一个关键评价来源。记录“为何追这个页面”和“它改变了什么”。如果只是多看一个相似标题，没有新信息，就停止。

优先问：同一家店为何有多个价格档？客户反复问什么却没有标准 SKU？加急/修改/小批量是否收费？看似不专业的页面到底有哪些可见交易信号？零售价差是否由规格与服务解释？这些问题能指向具体证据。

冷门与非标准交易可以进入观察列表，但“有人发布”不能证明有成交、合法或盈利。权利、资质、交付规则不清时，保留最小事实和待核查项，暂不推荐验证交易；不收集规避监管、欺诈或侵权的操作方法。

## 减少自己挑出来的幻觉

- 每个异常找一个普通同类或失败同类；不能只留吸引眼球的页面。
- 同一商家的多个页面标为关联样本，不夸大独立供给数量。
- 记录搜索词、入口、排序、登录状态和地区口径，承认推荐流与排名偏差。
- 评论区是公开表达样本，不代表全部客户；热评、商家展示的好评和疑似推广应分开描述。
- 需求者与供应者的匹配是研究假设；没有真实询价、履约和成交，不能写成已撮合的订单。
