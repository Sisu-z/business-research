# 换模型、双机和任务交接

## 不依赖某个聊天

README 指路，AGENTS 约定执行边界，HANDOFF 给当前检查点，`tasks/` 是唯一任务源，`data/` 和 `reports/` 承接实际产物。聊天只用于沟通，不假设下一模型能读取旧聊天或个人记忆。

模型先报告读到的授权、当前任务与证据，再执行分配范围。没有原始证据就明确不能复核原始观察；不能仅因仓库有条目就声称自己访问过该平台。

## 分工与资源

最多一个浏览执行者、一个窗口、一个任务标签；另一个页面替换当前页面。网站点击自动打开新标签时，确认页面归属并及时关闭多余页，绝不关闭用户原有页面。资源不足或用户要求暂停时停止导航、通知子代理、保存检查点，确认停止后再报告。

内部子代理适合校核、整理、翻译、文档和反证审查，可并行处理不同文件。不得让多个代理同时浏览或同时写同一文件；无需为每个子任务新建用户聊天。

第二台电脑不是默认加速器。若用户决定使用，可让其承担平台观察，本机做证据整理和筛选；两台不能同时抢同一组样本。默认整个项目仍只有一个浏览执行者，提升并发须先取得用户明确同意并确认资源。不复制任何登录状态；账号登录由用户在各机本人完成。

## 一次可接续的运行

在 [唯一任务](../tasks/README.md) 登记 `run_id`（如日期-机器代号-序号）、执行者、机器代号、基线提交、任务范围、可写文件、浏览权限和下一检查点。编号只是追踪记录，不是安全锁；由一个协调者串行分配。

开工先拉取基线和查未完成提交，不自动覆盖本地更改。各机用独立分支、会话文件和数据批次；样本ID遵循 [数据字典](data-dictionary.md)，整合时按平台及规范URL查重复。不要让两台机器直接覆盖同一个JSONL。

已有明确分工时可以直接推进。范围、付费、发布、联系、不可逆操作或用户暂停不能靠文字台账扩大授权。`main` 是已接收基线；后续协作建议分支/PR，轻量单人文档维护可直接提交，经授权推送。

## 交接至少留下这些

- 改了哪些文件、基线/提交、做到哪一步以及样本ID。
- 实际访问层级、失败与缺口；取得和未取得什么。
- 关键细节、一个最可能推翻解释的核查，而不是长篇商业结论。
- 当前运行/浏览状态，保留了几个任务页面，暂停或恢复授权是否存在。
- 原始证据是否只在本机、另一台是否实际拿到；文件映射只在私有记录中。

使用 [交接模板](../templates/handoff.md)，更新 HANDOFF 和当前任务。新机器只需克隆公共仓库就能理解项目；复现历史现场还需要复访或用户认可的私有证据传递，不承诺跨模型自动共享浏览器和运行历史。

当前项目没有自动调度、后台唤醒或定时采集。不为“方便接手”擅自安装常驻服务。
